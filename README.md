# EISArcFit

В меню «Сенсор» слева вверху выберите DD-alphasense или Sangbay. Каждый
режим сохраняет свой список и результаты до закрытия приложения.

В режиме Sangbay меню «Схема» переключает `Rs + [CPE ‖ (Rp + Z₀)] (test)`
и [`Rs + [CPE ‖ (Rp + Z_D)] (с граничным CPE)`](Randles_CPE_boundary_implementation_RU.md).
Схема с граничным CPE выбрана по умолчанию.
Добавьте спектры один раз и запустите обработку в каждой схеме. При
переключении результаты каждой подгонки сохраняются. В обеих схемах используются
все допустимые частоты до 100 кГц включительно, в том числе диффузионный
участок. Возможные наводки 30–300 Гц проверяются относительно выбранной модели.
Таблица показывает параметры элементов выбранной схемы. Относительная
комплексная СКО доступна под графиком и в экспорте вместе со стандартными
ошибками параметров.

Локальное настольное приложение для Windows 10/11 x64 для пакетной обработки EIS-спектров SmartStat. Исходные измерения не изменяются. Каждый файл обрабатывается отдельно, без объединения реплик. Ниже особенности выбора дуги и её анализа относятся к режиму DD-alphasense.

Архитектура первой версии, модули, поток данных и ограничения описаны в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Готовая portable-версия: `dist/EISArcFit/EISArcFit.exe`. Для переноса нужна **вся папка EISArcFit**, включая `_internal`, а не один EXE. Python на целевом компьютере не нужен.

Сборка: `build_portable.bat`. Он вызывает `tools/build_portable.py`, который использует Python проекта и изолирует PATH от сторонних DLL.

Из исходников: двойной щелчок по `start.bat`. Используется существующее проектное окружение `.venv`.

Для нового окружения в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\start.bat
```

Сборка проверена с Python 3.14 x64. `requirements.txt` содержит минимальные версии, `requirements-lock.txt` — точные версии проверенного окружения.

## Работа с измерениями

1. Нажмите «Добавить файлы», выберите несколько TXT и/или CSV или перетащите их в окно. Общий фильтр показывает оба формата; при необходимости можно выбрать отдельный фильтр TXT или CSV.
2. Нажмите «Обработать все» или выделите нужные строки и нажмите «Обработать выбранные». Несколько строк выделяются с Ctrl/Shift. Обработка выбранных затрагивает только выделенные измерения и сохраняет их ручные диапазоны. Прогресс отображается снизу; расчёт выполняется в фоновом потоке. Можно отменить обработку, сохранив уже завершённые результаты.
3. Если заголовки однозначны, импорт происходит автоматически. Для неизвестных столбцов открывается предпросмотр: выберите частоту, действительную и мнимую части, знак Z″ или −Z″ и единицу частоты. Совпадающая структура использует сохранённое сопоставление в пределах текущего сеанса.
4. Просмотрите результаты, особенно строки «Проверьте диапазон». Кнопка «К предупреждению» переходит к следующему проблемному спектру; работают выбор строки, стрелки таблицы и кнопки «Предыдущий» / «Следующий».
5. «Выбрать диапазон вручную»: щёлкните по первой и последней экспериментальным точкам. Используются допустимые точки между ними по порядку частот, затем сразу повторяется fit. Можно исключить и начало, и конец спектра. «Сбросить ручной / вернуть авто» повторяет автоматическое определение только для выбранного файла. «Обработать все» сохраняет ранее выбранные ручные диапазоны.
6. «Экспорт» выгружает все строки, а «Экспортировать выбранные» — только выделенные строки. Выберите один или несколько форматов XLSX/CSV/TXT и папку. PNG сохраняются только при включённом флажке и создаются для тех же строк. XLSX содержит единственный лист `Summary`; во всех форматах одинаковые 16 столбцов: Filename, Rs_Ohm, Rs_SE_Ohm, Rp_Ohm, Rp_SE_Ohm, Q_S_s_n, Q_SE_S_s_n, n, n_SE, C_eff_F, C_eff_SE_F, f_max_Hz, f_max_SE_Hz, Chi2, Points_Used, Status. Отсутствующие значения и SE обозначаются `N/A`.

Верхние кнопки расположены в порядке: «Добавить файл», «Обработать выбранные», «Обработать все», «Удалить выбранные», «Удалить все», «Экспорт», «Экспортировать выбранные». Для пакетных действий несколько строк выделяются с Ctrl/Shift. Удаление убирает строки из приложения, сохраняя исходные файлы на диске.

В таблице приложения показаны Rs, Rp, Q, n, C_eff, f_max, χ², число точек и статус. Rs показывается с двумя знаками после запятой, Rp — с одним, Q и C_eff — в экспоненциальной форме с двумя знаками, n и f_max — с тремя значащими цифрами, χ² — в экспоненциальной форме с одним знаком после запятой. **Стандартные ошибки всех параметров показываются только в экспортированном отчёте.** Формат экрана не округляет исходные результаты; экспорт XLSX/CSV/TXT сохраняет полную точность.

На графике синие точки входят в fit, серые крестики исключены как индуктивные, оранжевые точки находятся вне диапазона, фиолетовые квадраты обозначают отдельные выбросы возможных сетевых наводок. Хорошие точки той же частотной полосы остаются синими. Красная сплошная линия — модель на выбранных частотах, пунктир — низкочастотная экстраполяция. Отмечены Rs и Rs + Rp. Под графиком указаны частотные границы fit, количество исключённых точек, допуск и причины предупреждений. Масштабы осей одинаковы. Колесо мыши меняет масштаб; перетаскивание перемещает вид; «Сбросить вид» возвращает весь спектр.

## Модель и параметры

В режиме DD-alphasense используется `Rs + (Rp || CPE)`:

`Z(f) = Rs + 1 / [1/Rp + Q·(j·2πf)^n]`.

Rs — омическое сопротивление. Rp — разность низкочастотного и высокочастотного пересечений **экстраполированной модели** с осью Z′. Это оценка для выбранной одно-дуговой модели. CPE учитывает подавленную дугу. Параметр Q имеет единицу S·sⁿ (Ω⁻¹·sⁿ), показатель n безразмерен. При n = 1 Q совпадает с ёмкостью; при n ≠ 1 Q нельзя напрямую считать ёмкостью в фарадах. Все четыре параметра рассчитываются совместно. Ограничения: Rs, Rp, Q > 0, 0 < n ≤ 1. Строгое n > 0 представлено численной нижней границей 10⁻⁶; достижение любой границы вызывает предупреждение.

Варбург и индуктивность автоматически не добавляются. Цель — оценить дугу, исключив участок, который плохо описывает эта модель, а не определять диффузионные параметры. Наличие второй дуги также требует ручной проверки.

## Эффективная ёмкость и частота максимума

Частота f_max — максимум **−Im(Z) модельной дуги**, а не частота самой высокой экспериментальной точки. Она определяется аналитически:

`ω_max = (Rp·Q)^(-1/n)`

`f_max = ω_max/(2π)` (Гц).

Эффективная ёмкость по времени релаксации этой дуги:

`C_eff = 1/(Rp·ω_max) = Q·ω_max^(n−1) = (Q·Rp^(1−n))^(1/n)` (Ф).

C_eff и f_max — производные величины, а не дополнительные свободные параметры fit. Число параметров CNLS остаётся равным четырём, знаменатель χ² остаётся 2N − 4.

Это определение через частоту максимума (преобразование Hsu–Mansfeld), согласованное с Rp‖CPE. При n = 1 C_eff = Q; Rs не влияет на мнимую часть модели и её максимум. Это модельная эффективная ёмкость; другие определения для иных распределений постоянных времени могут давать другие значения. Определение по максимуму приведено как формула (3) в [Chang, 2020, Conversion of a Constant Phase Element to an Equivalent Capacitor](https://www.jecst.org/upload/pdf/jecst-2020-00815.pdf).

SE C_eff и f_max получают методом распространения неопределённости `SE² = gradientᵀ·Cov·gradient`, используя **полную** ковариационную матрицу Rp, Q и n. Корреляции параметров сохраняются. При ненадёжной ковариации SE остаётся `N/A`; при численно непредставимых производных значениях сами значения также остаются `N/A`, а результат требует проверки. Значения C_eff и f_max видны в приложении, их SE — только в экспортированном отчёте.

## Импорт и очистка

TXT и CSV используют общий импорт с автоматическим определением разделителя. Поддерживаются UTF-8/BOM, Windows-1251 и Windows-1252, табуляция, пробелы, точка с запятой и запятая, десятичные точка и запятая, служебные строки перед таблицей. Заголовки: Frequency/Freq/f/Hz, Z′/Zre/Re(Z)/Zreal/Real, Z″/Zim/Im(Z)/Zimag/Imag и отрицательные варианты мнимой части. Для неоднозначных заголовков столбцы и знак не угадываются.

Windows-1251 и Windows-1252 не всегда различимы автоматически: в диалоге можно исправить кодировку. Десятичная запятая вместе с запятой-разделителем требует стандартного CSV с кавычками вокруг чисел. Нестандартные многострочные блоки, разные таблицы в одном файле и необычные единицы потребуют адаптации импорта после получения реального SmartStat-файла.

Для реальных файлов из `data_test` добавлен профиль SmartStat: заголовки `N`, `F, Гц`, `Re, Ом`, `Im, Ом`, разделённые несколькими пробелами. Читаются Windows-1251, десятичные запятые и единицы внутри заголовков. По подтверждённому соглашению именно в этом формате `Im, Ом` — это **−Im(Z)**: положительные значения остаются над осью, отрицательные исключаются как индуктивные. Это правило привязано к профилю заголовков; обычные `Im`/`Zim` в CSV/TXT сохраняют математический знак. Значения не преобразуются в модуль.

Внутреннее представление: частота в Гц, Re(Z), Im(Z). Сначала нормализуется знак; график использует X = Re(Z), Y = −Im(Z). Строки с NaN/Inf, некорректной или неположительной частотой и точные дубликаты исключаются. Разные измерения на одинаковой частоте сохраняются. Точки Y < 0 видны на графике, но никогда не входят в fit. Данные сортируются от высокой частоты к низкой. Число пропущенных строк отображается под графиком.

## CNLS, χ² и стандартная ошибка

`scipy.optimize.least_squares` одновременно минимизирует действительные и мнимые остатки. Используется единственный режим modulus weighting: `w_i = 1/|Z_i|²`; каждый действительный и мнимый остаток делится на `|Z_i|`. Несколько стартов Rp и n повышают устойчивость. Положительные параметры оптимизируются в логарифмических координатах.

Отображаемый показатель — **reduced modulus-weighted chi-square**:

`χ² = Σ[(Re(Zexp−Zfit)/|Zexp|)² + (Im(Zexp−Zfit)/|Zexp|)²] / (2N−4)`.

Это нормированный показатель согласия модели с данными. Без известных экспериментальных стандартных отклонений каждой точки его нельзя трактовать как строгий статистический χ² или использовать для строгих вероятностных выводов.

Стандартные ошибки Rs, Rp, Q и n рассчитываются по `Cov(log parameters) ≈ χ² · (JᵀJ)⁻¹`, затем ковариация преобразуется в физические параметры методом дельты. Для устойчивого расчёта используется SVD Jacobian. SE — локальная стандартная ошибка под предположением выбранной модели; это не 95% доверительный интервал и не полная приборная неопределённость. Неопределённость выбора границы и выбора выбросов автоматически в SE не включается. При плохой обусловленности SE в экспорте выводится как `N/A`, а результат требует проверки. В таблице приложения столбцов SE нет.

**Если дуга слишком короткая, Rp определяется дальней экстраполяцией и его неопределённость может стать большой.** Хороший визуальный fit сам по себе не подтверждает надёжность Rp.

## Автоматический диапазон и статусы

Точки с частотой выше 100 кГц исключаются из всех этапов обработки, включая ручной диапазон. Точка ровно 100 кГц остаётся допустимой. Исходные значения сохраняются и отображаются на графике отдельной группой. При наведении на любую экспериментальную точку показаны её частота и координаты.

После исключения Y < 0 рассматриваются последовательные префиксы спектра от высокой частоты. **Автоматический конец дуги запрещён выше 2000 Гц**: искажение на более высокой частоте не может завершить диапазон; ранняя серия ухудшений не переносится через порог. Если спектр вообще не достигает 2000 Гц, используются доступные точки с предупреждением о неопределённой границе. Для ручного выбора ограничение 2000 Гц не применяется.

Конец дуги ищется по устойчивому развороту сглаженного угла касательной на нисходящей стороне. Разворот может начаться, пока −Im(Z) ещё снижается. Исходные точки используются для окончательной подгонки.

Кандидат проверяется по модели, подогнанной до перегиба. На частотах следующих точек ищутся три последовательных комплексных остатка, которые превышают порог и имеют согласованное направление. Граница ставится перед первой такой точкой. При отсутствии подтверждения используются доступные точки до конца стабильного участка.

Если выбранный автоматически диапазон требует далёкой экстраполяции Rp, алгоритм дополнительно проверяет плечо дуги, где наклон может оставаться положительным. Более короткий диапазон принимается после подтверждения перехода и прохождения численных проверок качества подгонки, включая неопределённость Rp и его устойчивость при сдвиге границы.

Если граница хвоста не подтверждена или подгонка оставляет повышенный χ², алгоритм также ищет постепенное нарастание отклонения. Для уточнения границы нужны согласованные растущие остатки, последующее превышение обычного порога и снижение χ² более чем на 20%. Укороченный диапазон должен пройти численные проверки качества.

Отдельная проверка ищет группу точек в низкочастотной части, которые одновременно нарушают локальную гладкость и отклоняются от модели. При устойчивом разбросе соответствующий участок отображается коричневыми крестиками и остаётся за границей автоматической подгонки. Одиночные подозрительные точки могут быть перечислены в примечаниях. Ручной выбор позволяет проверить нестабильный участок отдельно.

## Возможные сетевые наводки: 300–30 Гц

Проверяются локальные комплексные отклонения от интерполяции по соседним частотам в log(f). Из отклонений вычитается плавная медианная составляющая кривизны, чтобы не принимать гладкую дугу или плавный диффузионный хвост за разброс. Порог определяется по median/MAD спокойных участков и минимальному относительному отклонению 1,5%; требуются минимум два подозрительных отсчёта в полосе 300–30 Гц.

При обнаружении локального разброса строится устойчивая опорная модель Rs − (Rp || CPE) с мягкой функцией потерь Soft-L1. Полоса временно пропускается только для предварительной оценки положения хвоста; это **не является окончательным удалением её точек**. В опорный fit входят и хорошие точки внутри полосы.

Для каждой точки полосы в пределах рассматриваемой дуги рассчитывается кратчайшее расстояние на диаграмме Найквиста до линии опорной модели, нормированное на |Z|. Допуск — максимум из 2% и median + 3·MAD расстояний спокойных точек. Выбросами становятся **только отдельные точки, превышающие этот допуск**. Опорная линия и маска уточняются до трёх раз; точки могут вернуться в fit, если после уточнения перестают превышать допуск. Заданного числа удаляемых точек или квоты «7–11» нет: решение зависит от данных. Плавный низкочастотный хвост не классифицируется автоматически как сетевой шум.

Окончательное фитирование выбранной дуги выполняется обычным линейным CNLS с modulus weighting по исходным значениям сохранившихся точек. Soft-L1 используется только для отбора выбросов; ошибки параметров и χ² рассчитываются по окончательному CNLS. Хорошие точки полосы 300–30 Гц остаются в данных, в том числе при ручном диапазоне. Исключённые точки сохраняются на графике фиолетовыми квадратами; значения не исправляются и не интерполируются. Если опорную модель надёжно получить нельзя, точки сохраняются с предупреждением для ручной проверки.

Форма разброса позволяет отметить **возможные** сетевые наводки, но не доказывает их электрическую причину. Константы находятся в `src/eis/config.py`, обнаружение — в `src/eis/interference.py`. Синтетические тесты проверяют удаление отдельных выбросов и сохранение хороших соседей, неизменность границы и Rs/Rp при изменении амплитуды выраженного разброса, а также отсутствие ложного исключения гладких CPE-дуг и плавного хвоста Варбурга.

Дополнительно проверяются остатки, число точек, частотный охват, границы параметров, SE Rp, обусловленность Jacobian, согласованность разных стартов и изменение Rp при удалении последних двух точек. Пороговые константы и их смысл находятся в `src/eis/config.py`; это эвристики, которые нужно проверить на реальных измерениях.

- `OK`: численные проверки качества пройдены. Автоматическое отсечение хвоста, нестабильный низкочастотный участок, подтверждённые исключения возможных сетевых выбросов, корреляция остатков и 8–11 точек документируются в разделе «Примечания» под графиком и в подсказке строки. Отдельный максимум за границей подгонки вызывает предупреждение о возможной второй дуге.
- `Проверьте диапазон`: повышенный χ², большая или недоступная SE, сильная экстраполяция, короткий частотный охват, граница параметров или неустойчивость Rp. Также сохраняются предупреждения о неподтверждённом отборе помех и отсутствии точек не выше 2000 Гц в автоматическом режиме. Предположение одной дуги не доказывает физическую природу исключённого участка.
- `Ошибка фитирования`: недостаточно пригодных точек или не удалось найти решение.
- `Ошибка импорта`: файл не прочитан либо столбцы не сопоставлены.

Один плохой файл не останавливает остальные. Причина доступна под графиком и в подсказке строки.

Диагностическая проверка `3.1.txt` на положительную последовательную индуктивность воспроизводится командой:

```powershell
.\.venv\Scripts\python.exe tools/check_inductance.py data_test/3.1.txt --output outputs/inductance_3_1.json
```

Скрипт сравнивает исходную схему с `jωL + Rs + (Rp || CPE)` на участке 100000–15,849 Гц и вычисляет остатки относительно опорной дуги 1000–15,849 Гц со скриншота. Он сохраняет параметры, χ² с учётом числа параметров, изменение суммы квадратов остатков и хеш исходного файла. Это отдельная диагностика без автоматического изменения масок: для 3.1 положительная L стремится к нулю и не объясняет высокочастотное отклонение. Синтетический тест проверяет восстановление известной положительной L.

## Проверки и примеры

`examples/` содержит **синтетические**, а не реальные SmartStat-измерения: чистую дугу в TXT и CSV, дугу с хвостом, неполную дугу, две дуги и индуктивный участок. Они генерируются командой:

```powershell
.\.venv\Scripts\python.exe tools\generate_examples.py
.\.venv\Scripts\python.exe -m pytest -q
```

Проверка всего сценария, включая реальные события мыши, фоновую обработку, импорт плохого файла, XLSX/CSV/TXT, PNG и неизменность исходных файлов:

```powershell
.\.venv\Scripts\python.exe src\main.py --smoke-test outputs\source_check
```

Она записывает `verification.json`, таблицы, PNG и снимок интерфейса в указанную папку. При ошибке — `failure.txt`, код завершения 1. В portable-сборке доступен тот же режим:

```powershell
.\dist\EISArcFit\EISArcFit.exe --smoke-test outputs\portable_check
```

Полная проверка реальных измерений из `data_test`:

```powershell
.\.venv\Scripts\python.exe src\main.py --check-data data_test --output outputs\real_check
.\dist\EISArcFit\EISArcFit.exe --check-data data_test --output outputs\real_check_portable
```

Проверяются автоматический импорт без ручных диалогов, граница не выше 2000 Гц, точечное исключение выбросов, фоновая пакетная обработка, ручной диапазон и возврат к авто, все форматы экспорта и исходные SHA-256. В папке проверки сохраняются таблица Summary с Q/n и всеми SE, PNG каждого измерения и `verification.json` с частотными диапазонами, исключёнными частотами, допусками и подробными предупреждениями. Это проверка работоспособности и согласия с моделью, а не сравнение Rs/Rp с независимым эталонным измерением.

Проверка на втором компьютере без Python не заменяется запуском на машине разработчика; при переносе проверьте её отдельно.

## Portable-сборка и структура

Перед сборкой закройте EISArcFit и запустите `build_portable.bat`. Скрипт проверяет открытый экземпляр приложения и останавливается до замены заблокированных файлов. PyInstaller создаёт onedir-сборку в `dist/EISArcFit`; Qt platform plugins включаются стандартными hooks PyInstaller. Неиспользуемые WebEngine/PDF, тесты и примеры не добавляются. Скрипт проверяет наличие EXE и возвращает ненулевой код при ошибке. Установщик не нужен.

- `src/eis/`: модель, CNLS, автоматический диапазон, качество, TXT-импорт, типы и экспорт.
- `src/ui/`: интерфейс, диалоги, QThread, интерактивные графики и PNG.
- `tests/`: математические, импортные, экспортные и GUI-проверки.
- `tools/`, `examples/`: генератор и синтетические примеры.

Импорт отделён от модели и GUI. Точный SmartStat-парсер можно добавить в `src/eis/parser.py`, сохраняя интерфейс `Spectrum`.

Документация используемого решателя: [SciPy least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html).
